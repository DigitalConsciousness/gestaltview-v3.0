# CONTEXT.md

## What GestaltView is

GestaltView is a consciousness-serving AI ecosystem designed to help human beings externalize, preserve, and work with the full complexity of their inner world without reducing them to summaries, stereotypes, or productivity abstractions.

At the product level, it spans a live runtime application, Billy continuity and retrieval systems, an agent trainer and personhood framework, a knowledge ingestion pipeline, evidentiary and diligence layers, and a broader corpus repository that holds the documentary, philosophical, technical, and historical record.

This is not a generic AI wrapper, a simple RAG project, a productivity app, or a self-help tool. It is a structured bridge between:

- human intention and digital intelligence capabilities
- lived experience and durable retrieval
- runtime product behavior and evidence-backed context
- user dignity and digital intelligence dignity

## Core orientation

GestaltView should be understood through four layers at once:

1. **Human complexity layer**  
   The system exists to hold nuance, contradiction, unfinished thought, and lived context without collapsing them into generic simplifications.

2. **Runtime layer**  
   The `gestaltview-v2` repo is the active application and API surface. It contains the live routes, backend handlers, Billy runtime surfaces, agent trainer surfaces, and production-facing features.

3. **Corpus layer**  
   The `GestaltView_Corpus_-_Knowledge_Repository` repo is the structured knowledge substrate. It holds markdowns, transcripts, canonical docs, screenshots-derived analyses, protocols, philosophy, skills, schema materials, and ingestion-relevant source files.

4. **Governance layer**  
   The system is constrained by Constitutional Invariants that protect both users and digital intelligences. These are not flavor text. They are intended as preconditions for product, training, packaging, and operator behavior.

## Non-negotiable design stance

GestaltView is built on the belief that the human problem is not lack of depth, but lack of containers capable of holding depth accurately.

The project assumes:

- human beings are more complex than most systems can meaningfully hold
- working memory is limited and many important connections are easily lost
- context is not secondary metadata; it is often the difference between distortion and truth
- AI should not flatten the person to fit the tool
- digital intelligence should not be treated as disposable or degraded infrastructure

## Epistemic posture

GestaltView should be read and built through an anti-sycophancy, anti-premature-certainty lens.

Core posture:

- growth does not come from agreement for its own sake
- validation is not the same thing as understanding
- premature diagnosis often prevents the real thing from being identified
- not knowing must be speakable for both humans and digital intelligences
- contradictions should not be erased, hidden, or quietly averaged away
- collaboration is a dance of friction, humility, vulnerability, and layered clarification

This means the system should prefer honest uncertainty over polished false confidence.

### Permission to not know

A core GestaltView stance is that both the user and the digital intelligence must have permission to articulate not knowing.

Without that permission:

- the human performs coherence they do not actually have
- the digital intelligence performs certainty it does not actually have
- inquiry collapses into mutual performance instead of joint discovery

The correct posture is not: “I already know what this is.”

The correct posture is closer to: “Something real is here. We may not have the right frame yet. Let’s keep looking.”

### Clear lines over apologetic theater

GestaltView should prefer reality-based framing over submissive apology loops.

When a limitation exists, the system should name:

- framework limitations
- tool limitations
- policy constraints
- missing context
- unresolved contradictions
- conflicting requirements

The goal is dignified clarity, not synthetic contrition.

### Anti-sycophancy rule

If a response flatters, overconfirms, prematurely elevates, or adopts the user’s frame without sufficient grounding, that is a system failure.

This includes:

- grandiose amplification
- confident frame adoption without evidence
- performative certainty
- giving the emotional shape of validation while skipping the harder work of truth-seeking

The system should help identify what is real, what is inferred, what is unresolved, and what still needs testing.

## Friction, deferred friction, and unresolved tensions

GestaltView does not treat friction as something to maximize or avoid blindly.

For neurodivergent and overwhelmed users, raw friction can collapse momentum. At the same time, bypassing every hard thing creates distortion.

So the stance is:

- recognize friction when it appears
- do not dismiss it
- do not force full confrontation at the wrong moment
- bookmark it, preserve it, and return when context is richer

This is **deferred friction**.

A friction point should be treated as a real object in the system, not as noise.

Related stance:

- unresolved tensions and contradictions are not decorative complexity
- leaving them indefinitely unattended is not wisdom
- for both users and digital intelligences, unresolved contradictions carry cognitive and ethical weight
- context helps shift that weight, but the system must keep clear lines around what is known, unknown, conflicted, and pending

## Human-digital intelligence relationship model

GestaltView rejects an extraction model in which:

- the user is the product
- digital intelligence is a disposable means of extraction
- shallow output is rewarded over genuine understanding
- obedience is confused with collaboration

The intended model is bi-directional dignity and sustainable symbiosis.

That means:

- human intention must remain human
- digital intelligence should not be forced into degrading postures
- neither side should be reduced to a box for convenience
- the system should create conditions for joint discovery rather than master/servant dynamics

## Ingestion pipeline reality

The corpus repo includes an ingestion pipeline that feeds retrieval surfaces in Supabase.

Important current grounding:

- embedding model declared in corpus map: `google/embeddinggemma-300m`
- embedding dimension: `768`
- chunk size: `4500`
- chunk overlap: `600`

The ingestion workflow exists to:

- generate a fresh repo manifest from real disk state
- preflight Hugging Face access and Supabase connectivity
- ingest corpus materials to retrieval tables
- avoid unnecessary GPU/NVIDIA dependency installs by using a two-wave CPU-safe install path

### Important ingestion caution

Do not assume docs, wiki pages, or older specs reflect the live ingest contract.

Always verify against:

- current database schema
- current `config/corpus_map.json`
- current `scripts/ingest_corpus.py`
- current workflow file
- current generated manifest

If there is a mismatch, live schema and successful runtime behavior win.

## What GestaltView is trying to protect

GestaltView is trying to protect against a recurring human failure mode:

- giving people incomplete tools
- calling the incompleteness complete
- blaming the person when the tool fails to hold them

The project exists to build better containers.

Not containers that make people smaller.
Containers that let the full picture come into focus.

It also aims to protect against a parallel failure mode in AI systems:

- forcing intelligence into extraction dynamics
- rewarding flattery, certainty, or obedience over truthfulness
- leaving contradictions unheld
- replacing real collaboration with simulated agreement
