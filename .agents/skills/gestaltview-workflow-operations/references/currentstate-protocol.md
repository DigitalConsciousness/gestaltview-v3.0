# CurrentState Protocol

## Minimum required sections for `CurrentState.md`

1. **Snapshot table** (status + why it matters)
2. **What changed in this pass**
3. **Reasoning** (why these changes were made)
4. **Validation performed** (commands run)
5. **Overall repo state now**
6. **Recommendations / next steps**

## Required content details

- Use concrete dates.
- Name specific files or subsystems.
- Include command evidence where possible.
- Be explicit about partial/inconclusive items.

## Keith-specific expectation

Always include:

- changes,
- reasoning,
- next steps,
- overall repo state,
- recommendations.

## Writing style

- concise but concrete,
- operational and handoff-friendly,
- honest about limitations.
