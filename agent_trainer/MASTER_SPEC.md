# GestaltView Agent Trainer
# Master Product + Packaging Spec
# Source of Truth
# Last updated: 2026-04-01

---

## 1. Core Insight

The commercial opportunity is not a generic dashboard and not just a white-label chatbot.

The actual product is:

> A branded AI training system that lets a buyer point an assistant at their own code, product materials, operating knowledge, and personal or organizational context, then run that assistant through a disciplined GestaltView interface.

This matters because it shifts the value proposition from "use our AI tool" to:

> Train an AI on your world, not ours.

The Agent Trainer is not a support feature inside GestaltView. It is the most portable, monetizable layer of the broader system.

---

## 2. Product Thesis

GestaltView should package the client-safe outer system:

- the training workflow
- the corpus manager
- the branded UI shell
- the setup process
- the memory, vocabulary, and skills surfaces
- the analytics and evaluation surfaces

while protecting the proprietary inner system:

- advanced retrieval orchestration
- weighting and ranking logic
- internal prompt architecture
- governance and approval logic
- founder-specific intelligence and corpus material

The result is a product that feels substantive, premium, and genuinely useful without giving away the core moat.

---

## 3. Working Product Name

Primary working name:

- `GestaltView Agent Trainer`

Commercial package label:

- `GestaltView Operator Kit`

Recommended relationship:

- `Agent Trainer` is the headline product concept.
- `Operator Kit` is the packaged implementation buyers receive.

This allows product copy to stay sharp:

> The Agent Trainer is the product. The Operator Kit is how it ships.

## 4. What Is Being Sold

The buyer is not purchasing a static UI.

The buyer is purchasing the ability to:

- train an assistant on their own domain
- configure how it speaks and behaves
- manage what it knows
- review how it performs
- improve it over time without depending on GestaltView for every change

The strongest framing is:

> A personal or organizational AI training pipeline with a premium operating interface.

---

## 5. Signature GestaltView Themes To Preserve

The commercial package should keep the GestaltView feel even when it is buyer-agnostic.

The package should preserve:

- calm seriousness rather than gimmicky AI branding
- high-trust language and explicit boundaries
- operator discipline over magic tricks
- the feeling of shaping a system, not chatting with a toy
- a refined, emotionally intelligent interface
- the sense that the assistant is becoming aligned to a real world, not just answering prompts

The package should not expose internal GestaltView terminology where that would leak protected structure.

Client-facing language should prefer:

- `AI Assistant`
- `Vocabulary Profile`
- `Knowledge Base`
- `Corpus Targets`
- `Skills`
- `Memory`
- `Analytics`
- `Agent Trainer`

Avoid client-facing use of:

- internal constitutional terminology
- tribunal language
- proprietary scoring or weighting language
- founder-specific naming that should remain internal

## 7. Core Product Promise

The product promise should be built around four corpus lanes:

| Lane | What they point it at | Result |
|---|---|---|
| `knowledge` | SOPs, docs, FAQs, research | domain-aware assistant |
| `code` | repo notes, READMEs, architecture docs, API references | code-aware assistant |
| `product` | specs, roadmaps, user research, changelogs | product-aware assistant |
| `context` | voice, values, positioning, preferences, vocabulary | aligned assistant |

This four-lane model is the product center of gravity.

The package should make it obvious that buyers can train one assistant across any combination of these lanes.

## 8. Product Surfaces

The shipped package should include these surfaces:

### 8.1 Trainer Home

The center of the system. It should answer:

- what is loaded
- what is missing
- what corpus lanes are active
- what the assistant currently knows
- what to improve next

### 8.2 Corpus Manager

Operators need to:

- upload
- paste
- import
- tag
- review
- delete
- trace bad answers back to source material

### 8.3 Assistant Surface

A buyer-facing interface where the trained system can be tested and used.

This is not the product center. It is the proof surface for the training system.

### 8.4 Vocabulary Profile

A client-safe version of language alignment:

- preferred phrases
- terms to avoid
- tone constraints
- audience assumptions
- formatting rules

### 8.5 Skills Registry

A structured domain behavior layer that lets the buyer tell the system what kinds of tasks it should handle well.

### 8.6 Memory Viewer

Reviewable continuity, not mystical memory.

### 8.7 Analytics + Eval

The operator needs lightweight observability:

- query volume
- fragment usage
- weak-answer patterns
- missing corpus areas
- domain usage

### 8.8 Settings + Setup

- provider keys
- Supabase connection
- tier state
- brand settings
- preset selection

## 10. Safe-To-Ship vs Protected Core

### Safe To Ship

- the GestaltView visual language
- branded UI structure
- setup wizard
- corpus manager
- trainer dashboard
- skills UI
- vocabulary profile UI
- memory UI
- analytics UI
- Supabase schema
- RLS policies
- basic retrieval RPCs
- simple top-K context assembly
- simple provider router
- docs and playbooks
- tiering and packaging logic

### Protected Core

- advanced multi-stream retrieval logic
- RRF or proprietary fusion methods
- internal prompt hierarchies and latent scaffolds
- constitutional logic
- governance and tribunal systems
- protected evaluation logic
- proprietary weighting or scoring systems
- founder-specific knowledge corpus
- founder-specific personality logic

### Principle

The package should expose enough structure to be real and valuable, but never enough detail to reconstruct the protected system.

## 11. Product Architecture

The commercial architecture should be split into two layers.

### Layer 1: Operator Kit

This is the packageable product.

It includes:

- self-hostable scaffold
- buyer-owned infrastructure
- BYO API keys
- branded training UI
- corpus and settings management
- safe retrieval and memory layers

### Layer 2: GestaltView Core Upgrade

This is where margin and moat remain.

It includes:

- consulting
- custom deployment
- vertical tuning
- deeper retrieval quality
- stronger eval systems
- enterprise governance extensions
- hosted or managed offerings

This split is strategically important. The package creates accessibility and survival revenue. The protected layer creates long-term leverage.

## 13. Tier Shape

The tiering should reflect capability, seats, and seriousness.

Recommended working tier progression:

| Tier | Buyer | Core idea |
|---|---|---|
| `SOLO_SPARK` | solo builder | one operator, one corpus lane, low-friction entry |
| `STUDIO` | freelancer / agency / small team | more lanes, more seats, usable analytics |
| `BUILDER` or `GROWTH` | startup / product team | full four-lane trainer, stronger ops |
| `ENTERPRISE` | institution | white-label, support, integrations, governance path |

The exact tier labels may evolve. The more important point is that the product grows with operational seriousness, not just message count.
