---

## Purpose

Operationalize the embodiment profile system by establishing a reliable, repeatable pipeline that:

1. Reads all `*.embodiment.json` files from `embodiment_profiles/`
2. Validates them against `shared/embodiment/types.ts`
3. Upserts them into the Supabase `embodiment_profiles` table
4. Regenerates `shared/embodiment/generated.ts` as a type-safe static registry

This is the foundational data layer. Nothing else in the embodiment system (Billy prompting, Trainer, Council, Studio) should be wired until this pipeline is stable and verified.

---

## Principles

- **Evidence first.** Do not invent new schema. Map what exists in the JSON files to what exists in `shared/embodiment/types.ts` and `supabase/`. Surface mismatches as warnings, not errors.
- **Idempotent.** Running the sync twice must produce the same result. No duplicates, no orphan rows.
- **Non-destructive.** This slice does not modify any UI files, runtime bindings, or agent behavior. It only touches data and the generated registry.
- **Fail loudly.** If a profile is malformed or required fields are missing, log it clearly and skip that profile. Never silently swallow bad data.
- **Founder-review gate.** Profiles marked `visibilityScope: "founder-only"` or `profileStatus: "experimental"` must be flagged in the output and must not be exposed to public surfaces.

## Intent

The sync script (`scripts/sync-embodiment-profiles.ts`) already exists in partial form. The goal is to complete it so that:

1. It walks `embodiment_profiles/` recursively, finding all `*.embodiment.json` and `*.json` files that are not prefixed with `_`.
2. For each file, it parses the JSON and extracts or derives a `slug` (from the filename or `slug` field in the JSON).
3. It validates required fields against `shared/embodiment/types.ts`. Required fields at minimum:
   - `slug` (string, URL-safe, unique)
   - `publicName` (string)
   - `profileStatus` (enum: `"draft"` | `"active"` | `"archived"` | `"experimental"`)
   - `visibilityScope` (enum: `"public"` | `"founder-only"` | `"internal"`)
   - `readinessScore` (number 0–100)
4. It upserts each valid profile into the Supabase `embodiment_profiles` table using `slug` as the conflict key.
5. After all upserts, it reads back all active/public profiles from Supabase and writes a fresh `shared/embodiment/generated.ts` containing:
   - A `EMBODIMENT_REGISTRY` const (Record<slug, EmbodimentProfile>) of all profiles
   - A `PROFILE_SLUGS` const (string[]) of all slugs
   - A `getProfile(slug: string): EmbodimentProfile | undefined` helper
6. It prints a summary: profiles synced, profiles skipped (with reasons), profiles written to registry.

---

## Exact Behavior

### On missing required fields
Log a warning:
```
[SKIP] billy — missing required field: readinessScore
```
Do not upsert. Do not crash. Continue to next profile.

### On slug collision in the same run
Log an error and skip the duplicate:
```
[SKIP] billy — duplicate slug found in: embodiment_profiles/council/billy.json (already processed from embodiment_profiles/billy.embodiment.json)
```

### On Supabase upsert failure
Log the error with the slug and HTTP status. Do not crash. Continue.

### On `generated.ts` write
Always write, even if some profiles were skipped. The registry should only contain profiles that successfully upserted to Supabase.

### Founder-only profiles
Include in Supabase upsert (they must persist). Exclude from `generated.ts` unless the generator is invoked with a `--include-founder-only` flag. Default: exclude from generated registry.

## Validation Commands

```bash
# 1. Dry run — validate profiles without upserting
npx tsx scripts/sync-embodiment-profiles.ts --dry-run

# 2. Full sync
npx tsx scripts/sync-embodiment-profiles.ts

# 3. Verify generated registry exists and compiles
npx tsc --noEmit

# 4. Spot-check a slug in the registry
node -e "import('./shared/embodiment/generated.ts').then(m => console.log(Object.keys(m.EMBODIMENT_REGISTRY)))"

# 5. Check Supabase row count matches expected
# (run in Supabase SQL editor or via MCP)
SELECT COUNT(*) FROM embodiment_profiles;
```

## Expected User-Visible Result

After running `npx tsx scripts/sync-embodiment-profiles.ts`:

1. Terminal prints a clean summary table of synced/skipped profiles.
2. `shared/embodiment/generated.ts` is updated with all active public profiles.
3. `npx tsc --noEmit` passes with no new errors.
4. Supabase `embodiment_profiles` table has one row per valid JSON profile.
5. Billy, Trainer, and other runtime surfaces can now import `generated.ts` and resolve profiles by slug without touching the DB on every request.

## Risk Notes

- The `embodiment_profiles/` directory contains nested subdirectories (`council/`, `reference/`, `character_studies/`). The walker must handle depth correctly. Reference and character study files may not conform to the profile schema — they should be skipped gracefully, not errored on.
- `shared/embodiment/types.ts` may not yet have all fields that exist in the JSON files. If Codex finds extra fields in the JSON that are not in `types.ts`, it should add them to the type as optional fields with a comment `// discovered field — needs review`.
- Do not add a `createdAt` / `updatedAt` to generated.ts — those are DB concerns, not registry concerns.

---

## Rollback Notes

- `generated.ts` is a generated file. If the sync produces bad output, restore from git: `git checkout shared/embodiment/generated.ts`
- Supabase rows can be cleared per-profile by slug if needed. No cascading deletes are expected from this table alone in this slice.
- No UI changes means no user-visible rollback needed.
