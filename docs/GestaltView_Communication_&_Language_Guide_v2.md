## Purpose

This guide governs how GestaltView presents itself — in documentation, public-facing copy, social content, portfolio pages, and agent responses.

The original version of this guide overcorrected. It told you to remove claims it hadn't seen the evidence for. You have the evidence. This version knows the difference between **things that happened** and **things that need translation for a cold audience**. Those are different problems with different solutions.

**Core principle:** The work is real. The receipts exist. The job is accurate translation — not deflation.

---

## The Three-Lane Framework

Before writing or auditing any copy, assign each claim to a lane:

| Lane | Definition | Treatment |
|------|-----------|-----------|
| **Lane 1: Documented** | Happened. Verifiable. Timestamped. | Cite it directly. Name the evidence. |
| **Lane 2: Real — Needs Translation** | Happened, but the current framing triggers skepticism before comprehension | Reframe the container, not the claim |
| **Lane 3: Design Target / Aspirational** | True intent or projected outcome, not yet measured | Label explicitly as target or projection |

The failure mode is treating Lane 1 as Lane 3. That's what the previous version did.

## Part II: Lane 2 — Real Events, Wrong Container

These things happened. The current framing is the problem — not the underlying truth.

### The Tribunal of Understanding

| Current framing | Why it misfires | Accurate reframe |
|-----------------|-----------------|-----------------|
| "Unprecedented validation by seven AI systems" | "Unprecedented" reads as marketing; "validation" implies peer review | "Multi-model structural convergence documented across 7 isolated sessions — used as adversarial critique and architectural consensus-checking, not clinical validation" |
| "Seven AI systems independently converged" | "Independently" is challenged because same operator | "Seven systems given isolated prompts reached the same structural conclusion. The isolation protocol and session logs are documented and timestamped." |
| "Tribunal of Understanding" as proof | Strong framing that needs a one-sentence explanation | Add: "A governance protocol — not a marketing term — embedded in BillyEngine.ts as a ManifestNode with linked evidence." |

**Rule:** The Tribunal is real. The word "validation" is the wrong container for a research-literate audience. Use "convergence," "structural recognition," or "consensus-checking" instead. The substance doesn't change.

## Part III: Lane 3 — Design Targets (Label Them)

These are real goals. They are not yet measured. Say that plainly — it's more credible, not less.

| Claim | Actual Status | How to say it |
|-------|---------------|---------------|
| 95% conversational resonance | Design target | "Design target: 95% conversational resonance. Not yet formally measured." |
| Crisis detection accuracy | Implemented, untested at scale | "Crisis signals trigger before any LLM call. Real-world accuracy at scale: unstudied." |
| ADHD executive function support | Functional prototype | "ADHD support prototype — functional, not clinically validated. IRB and clinical partnership are the right next step." |
| PLK conversational fingerprinting | Implemented as system prompt strategy | "PLK: implemented and operational. Formal efficacy measurement: not yet conducted." |
| Clinical deployment to vulnerable populations | Not started | Say this proactively: "No clinical studies conducted. Deployment to vulnerable populations requires IRB approval, clinical partnership, and informed consent architecture. That work hasn't happened yet — it's the correct next step." |

**Rule:** Saying "not yet" first is both ethical and strategically credible. Vulnerable users have been burned by people who skipped this. Naming it preempts the question and builds trust.

## Part V: Audience-Specific Tone

### Reddit / Public Building (r/Gestalt_View, r/startups, build-in-public)
- One specific thing at a time. Never the whole vision at once.
- Show the problem. Show how the code addresses it. Stop there.
- Acknowledge what isn't done yet before anyone asks — it reads as integrity, not weakness.
- "This is what I built and why" lands better than "this will change everything."

### Portfolio / Vercel / GitHub README
- Lead with the user's problem, not the framework vocabulary.
- Architecture diagrams and code snippets over manifestos.
- Credentials once, plainly: Pepperdine quarter-finals, Founders Network, 10 months solo, public repo.
- One clear call to action: "See the code" or "Try Billy."

### Investor / Research Conversations
- State the problem, the population, the gap in existing tools.
- Show the working system first.
- Name what validation is still needed and exactly why it hasn't happened yet.
- The Tribunal convergence is a development methodology story, not a validation story — frame it that way.
- Ask for partnership, not belief.

### Vulnerable Users
- Never promise outcomes.
- Surface crisis resources before they're needed — the crisis detection protocol runs before any LLM call by design.
- "This might help" is honest. "This will change your life" is not.
- The Genesis Protocol and Never Look Away are design values. State them as design values.

## Part VI: The One-Sentence Test

Before publishing anything:

> *"Would a skeptical clinical researcher — or a person who has been let down by ten other apps — read this and feel respected, or feel sold to?"*

If sold to: check which lane the claim is in. If it's Lane 1, you don't need to soften it — you need to show the evidence. If it's Lane 3, label it as a target.

The goal is never to make GestaltView smaller. It's to make it legible to people who haven't yet seen the receipts.
